# 薯条校园

面向吉首大学四个校区的代课互助平台前端原型。线上访问地址：

```text
https://fries-campus-2026.oss-cn-beijing.aliyuncs.com/
```

## 已实现

- 四个校区独立选择：砂子坳校区、大田湾校区、雷公井校区、张家界校区
- 订单大厅、发布代课、状态筛选与关键词搜索
- 发单无需认证；接单员上传学生身份资料，管理员审核通过后才能接单
- 信息簿：保存常用课程、校区、地点、联系方式和备注，发布时可一键填写
- 余额系统：充值赠送、订单收入结算、管理员调整余额
- 完成订单需接单员拍照上传凭证，发单方确认收货后收入才进入余额
- 提现需联系管理员微信 `Hurrkan`
- 管理员后台：搜索用户、搜索订单、认证审核、取消认证、调整余额
- 7% 平台服务费：发单方支付订单金额，接单方到账订单金额的 93%
- 支付适配层：余额支付、沙箱支付、微信支付、支付宝

## 打开方式

管理员后台已部署到独立的云端接口，登录校验、密码校验和权限判断均在服务端完成，公开页面不包含管理员密码。

## 7% 服务费规则

- 发单方支付：订单金额
- 平台服务费：订单金额 × 7%
- 接单方到账：订单金额 × 93%

例如订单金额 `¥100.00`，服务费 `¥7.00`，接单方到账 `¥93.00`。

## 订单与结算流程

1. 发单方发布订单并支付，资金进入平台托管。
2. 认证通过的接单员接单。
3. 接单员完成后上传照片凭证。
4. 发单方确认收货。
5. 平台把接单方收入的 93% 计入余额。

取消待接订单时，如果原支付方式为余额，会自动退回余额。

## 充值赠送

当前演示规则：

- 充值满 50 送 3
- 充值满 100 送 8
- 充值满 200 送 20
- 充值满 500 送 60

这些规则位于 `app.js` 的 `RECHARGE_GIFTS`，可以按运营策略调整。

## 接入真实支付需要什么

要让其他客户真实付款下单，至少需要准备以下内容：

### 1. 企业或个体商户资质

- 微信支付：需要营业执照、对公账户或法人银行账户、经营场景说明。
- 支付宝：需要企业支付宝账号或个体工商户支付宝账号。
- 如果只是测试，可先申请微信支付或支付宝的沙箱环境。

### 2. 服务端

支付不能只靠前端完成，必须有一个服务端负责：

- 保存订单和用户余额
- 调用微信支付或支付宝下单接口
- 保存支付密钥
- 接收异步支付回调
- 验签并更新订单状态

推荐服务端能力：

```text
POST /api/payment/wechat/create
POST /api/payment/wechat/notify
GET  /api/payment/wechat/query
POST /api/payment/alipay/create
POST /api/payment/alipay/notify
GET  /api/payment/alipay/query
```

### 3. 支付参数

微信支付通常需要：

- AppID
- 商户号 MchID
- API v3 密钥
- 商户证书私钥
- 证书序列号
- 回调通知地址

支付宝通常需要：

- AppID
- 应用私钥
- 支付宝公钥
- 异步通知地址

### 4. 前端接入点

当前 `payment.js` 已经预留适配层。以微信支付为例，把模拟逻辑替换为服务端请求：

```js
create(order) {
  return fetch("/api/payment/wechat/create", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify(order),
  }).then((res) => res.json());
},

confirm(payment) {
  return poll("/api/payment/wechat/query", {
    transactionId: payment.transactionId,
  });
}
```

前端不应直接判断“支付成功”。必须由服务端收到微信或支付宝回调并验签后，再更新订单状态。
